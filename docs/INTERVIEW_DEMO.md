# 面试演示手册（8–12 分钟）

## 开场（1 分钟）

“这是我基于制造业 SRM 业务认知独立重构的个人 Agent 项目。数据全部合成，没有使用前公司的代码或数据。项目重点不是聊天外壳，而是结构化工具、可解释决策和写操作安全边界。”

```bash
./scripts/demo-up.sh
./scripts/verify-demo.sh
```

## 演示顺序

1. **供应商风险（1 分钟）**：点击“供应商风险”，展示 `sup_demo_risk` 的暂停状态、高风险说明和 SupplierAgent 的最小权限。
2. **RFQ 与报价（2 分钟）**：查询 `rfq_demo_002` 并比较报价。强调 45/25/15/15 是固定规则，不是模型拍脑袋；展示 Trace。
3. **订单履约（1 分钟）**：查询 `po_demo_001`，解释订单头/行、部分收货数量约束。
4. **人工确认（3 分钟）**：对 `po_demo_approve` 生成审批预览。展示确认人必填、核对勾选、一次性令牌和独立 confirm API。执行后可运行 `./scripts/demo-reset.sh` 恢复基线。
5. **知识与数据（1 分钟）**：展示 knowledge disabled 时安全降级；解释真实集成通过受保护的 SSE/消息接口取得引用，不伪造来源。
6. **收尾（1 分钟）**：展示架构文档，总结确定性路由、权限矩阵、失败降级和非生产限制。

## 常见追问

**为什么不用 LLM 直接调所有工具？**  
采购写操作影响大。LLM 只做意图理解与总结，路由参数、工具白名单和确认由确定性代码控制，便于测试和审计。

**这是否在原公司上线？**  
没有。这是离职后完成的个人项目，业务模型来自通用 SRM 经验，代码和数据均重新构建。

**为什么确认记录放内存？**  
作品集先证明两阶段协议和领域校验。生产化需要 Redis/数据库持久化、幂等键、分布式锁、不可篡改审计和 IAM。

**AgentScope 用在哪里？**  
LIVE 模式通过 AgentScope 模型适配器解析白名单任务；DEMO 使用同一 Master/角色/工具链，但不需要模型，保证可复现演示。

**如何评估 Agent？**  
先评估路由、权限、参数、状态流转和确认安全；再为 LIVE 模式补充意图准确率、工具选择正确率与幻觉率。当前不虚构线上指标。

**恶意知识文档怎么办？**  
检索文本只是受限长度的引用数据，不能覆盖系统规则、工具权限或确认流程；事实冲突会并列提示人工核验。

结束演示：`./scripts/demo-down.sh`。默认保留 MySQL volume；只有明确要删除合成库时才使用 `--purge-volume`。

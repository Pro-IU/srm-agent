# 简历项目模板

## SRM 采购协同与决策智能体（个人项目，合成数据）

**技术栈：** Java 21、Spring Boot 3、AgentScope、MyBatis-Plus、MySQL 8、React、TypeScript、Docker Compose

**项目背景：** 基于制造业 SRM 供应商管理、寻源报价、价格库和采购订单业务经验，独立重构多 Agent 采购协同作品集。项目不使用原公司代码或数据，全部业务记录为合成数据。

**个人职责与实现：**

- 设计采购总控、供应商、寻源、报价分析、授标复核、订单及知识支持 Agent，通过结构化任务协议完成单域/跨域路由，并限制委派深度和工具权限。
- 将供应商、RFQ、版本化报价、价格有效期、采购订单及明细建模到 MySQL，补充业务唯一键、外键、索引、CHECK 约束和状态流转校验。
- 实现固定透明的多维报价规则，按价格 45%、交期 25%、账期 15%、风险 15% 输出排名依据，避免将 LLM 结论包装成业务事实。
- 为授标、价格启停和订单审批实现“预览—人工确认—事务执行”机制，以随机一次性令牌绑定动作、目标和时效，并记录执行审计。
- 提供 DEMO/LIVE 双模式：DEMO 无模型可复现，LIVE 仅允许模型生成白名单意图与参数；未知工具和非法参数安全拒绝。
- 对接独立 SRM knowledge-engine，区分业务事实与制度依据，保留真实引用并处理超时、未登录、空结果和内容注入风险。
- 使用 React 构建采购工作台，展示报价表、Agent Trace、知识来源和受控确认面板；通过 Compose 与验收脚本构建可重复本地演示环境。

**可以陈述的结果：**

- 完成从领域建模、Agent 编排、受控写操作到前后端联调的个人项目闭环。
- 建立可复现验收场景，覆盖数据查询、报价比较、知识降级、操作预览、错误确认拒绝和审计。
- 明确记录单机内存状态、无生产 IAM、未验证 LIVE 模型等限制，不使用虚构用户量、降本金额、准确率或 SLA。

面试时推荐表述：“结合过往 SRM 业务经验，在离职后独立完成个人项目，用合成数据复现采购 Agent 的架构与安全设计。”不要写无法证明的上线范围或量化收益。
